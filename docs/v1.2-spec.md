# Plainfold 1.2 implementation contract

Owner-approved decisions, 2026-10-30. This file is the shared contract for the
v1.2 work. Do not change an interface here without updating this file and
telling the integrator.

## Approved decisions

- **Safety floor (never disableable):** Settings, open/switch repository, the
  repository tree, the editor, Save, close/unsaved-change guard, error/status
  notices, window controls, encoding and read-only guards.
- **Disable semantics:** hide the control everywhere, block its shortcut and
  action, keep existing data. Settings is the only place to restore it.
- **Granularity:** 21 feature groups plus per-control advanced toggles.
- **Settings UI:** left category navigation, search, auto-save, per-section
  reset; no Save/Cancel footer.
- **Repositories:** one active repository. A Repositories section above Pinned
  and a matching list on the welcome screen switch between saved repositories.
  Launch reopens the last active repository, unless a startup repository is set
  (the existing `defaultRepository` setting wins).
- **Rescan:** remove the toolbar button. "Rebuild search index" becomes an
  action in Settings > Maintenance.
- **Updates:** automatic GitHub Releases check on launch, notify only, never
  download. Placeholder owner/repo, default on, inert until configured. The
  only network destination is `https://api.github.com`.
- **Release:** next version is 1.2.0. Build the front-end bundle and the release
  binary only; no installers in this round.
- **Rollback point:** commit `dcc676e`, annotated tag `v1.1.27`.

## Settings schema (Rust and JS)

New camelCase settings fields:

```json
{
  "disabledFeatures": [],
  "recentRepositories": [],
  "lastRepository": null,
  "recentRepositoryLimit": 8
}
```

- `disabledFeatures: string[]` default `[]`; sanitize trim/dedupe/cap 200 ids,
  preserve unknown ids for forward compatibility.
- `recentRepositories: string[]` default `[]`; most recent first, canonical
  absolute paths, deduplicated, max 20. Server-managed: the front end never
  edits this field directly.
- `lastRepository: string | null` default null. Server-managed.
- `recentRepositoryLimit: u32` default 8, clamp 1-20.
- Existing fields unchanged. Missing files still default silently.

`Settings::feature_enabled(id)` returns false only when `id` is in
`disabledFeatures`. Backend enforcement uses the group ids `watcher` and
`revisions`.

`save_settings` must preserve the server-managed `recentRepositories` and
`lastRepository` values from the running state, ignoring whatever the front end
sent, so a settings save cannot erase the list.

## Snapshot and repository commands

`Snapshot` gains:

```json
"recentRepositories": [
  { "path": "C:\\\\Notes", "name": "Notes", "exists": true }
]
```

`RepositoryEntry { path, name, exists }`, camelCase. `exists` is computed from
the filesystem at snapshot time.

Bootstrap order: `defaultRepository`, then `lastRepository`, then the welcome
screen. A missing/failed stored repository produces a plain notice but does not
crash or delete the entry.

Opening a repository successfully must:
1. Move its canonical path to the front of `recentRepositories`.
2. Set `lastRepository`.
3. Save settings atomically, best-effort; a settings save failure must not
   prevent the repository from opening.

New command:

```
remove_recent_repository(path: String) -> Vec<RepositoryEntry>
```

- Refuses to remove the currently open repository ("Switch to another
  repository before removing this one.").
- Removes the entry, updates `lastRepository` if it pointed at the removed
  path, saves settings, returns the refreshed list with `exists`.
- Never deletes repository files.

## Settings UI

Left navigation categories:

1. **Appearance** - theme, font family, font size, editor zoom reset.
2. **Editor** - tab width, wrap default/feature state, autosave, revisions
   retention, editor statistics.
3. **Sidebar & Tree** - pinned/recent limits, default sort, tree filtering,
   sort/drag, create/delete.
4. **Search** - search feature state, index information, Rebuild index.
5. **Repositories** - startup repository, reopen-last explanation, recent
   repository limit, saved list with remove.
6. **Updates** - auto-check toggle, Check now, current/latest/last checked,
   update source status.
7. **Features** - all 21 groups with switches, grouped Browsing / Editing /
   Application, each expandable to its advanced controls.
8. **Maintenance** - Rebuild search index (moved Rescan), clear recent
   repositories, reset all settings.
9. **About** - version, update source, GitHub placeholder, plain-language note.

Auto-save rules:

- Checkboxes/selects save immediately.
- Text/number inputs debounce 500 ms; closing the dialog or pressing Enter
  flushes pending changes.
- Never close on a validation/save error. Show the message inline.
- After a successful save, call the normal `applySettings` path, update
  `state.savedSettings`, and show a brief "Saved" indicator.
- Per-section Reset restores only that section's keys and feature flags.
- Search filters fields by label, help text, and key; empty matches show
  "No settings match".
- The Settings button remains the only permanently visible app control.

## Repository switcher UI

- Sidebar section **Repositories** directly above Pinned, visible only when the
  `recentRepositories` feature is on. Shows up to `recentRepositoryLimit`
  entries, active entry marked, most recent first.
- Each inactive entry: click switches; a remove control appears on hover/focus.
  Missing entries are disabled and labelled "Missing".
- The welcome screen shows the same list above the Open a folder button.
- Switching asks the unsaved-changes question, shows the repository loading
  overlay, calls `openRepository`, and applies the snapshot. Only one repository
  is active at a time.
- Removing the active entry is refused by the backend and the UI.
- The Repositories section is hidden when the feature is off; Open Repository
  and switching remain available via the core button.

## Update checker

Create `src/updater.js`:

- `UPDATE_OWNER = "your-github-user"`, `UPDATE_REPO = "plainfold"`.
  `updateSourceConfigured()` is false while the owner is the placeholder.
- `compareVersions(a, b)` compares numeric `X.Y.Z` versions, tolerating a
  leading `v` and ignoring pre-release suffixes.
- `checkForUpdate({ currentVersion, fetchImpl })` calls
  `https://api.github.com/repos/<owner>/<repo>/releases/latest` with
  `Accept: application/vnd.github+json`, `cache: "no-store"`, and an 8 s abort
  timeout. It ignores drafts/prereleases, accepts `tag_name`/`html_url`, and
  returns `{ configured, currentVersion, latestVersion, updateAvailable,
  releaseUrl, error }`. It never throws for network/HTTP problems.
- A launch check runs at most once per 24 h, after bootstrap and without
  blocking UI. Cache keys in `localStorage`:
  `plainfold.update.lastCheck` (ms) and `plainfold.update.dismissed` (version).
- An update shows a dismissible banner below the top bar: "Plainfold <version>
  is available." with Release notes and Dismiss. Dismiss stores the version.
- Settings > Updates shows source status, current/latest version, last checked,
  "Check now", and the auto-check switch (`updates.autoCheck`).
- Opening a release link goes through a new command `open_update_page(url)`
  that only accepts `https://github.com/` URLs (no whitespace/control chars,
  max 2048) and uses the existing `opener` crate.
- CSP adds `https://api.github.com` to `connect-src`. No download, no telemetry,
  no other host.
- Update docs: network is allowed only for this optional check and can be
  disabled in Settings.

## Rescan move

Delete the toolbar `#rescan` button and its wiring. Add a Maintenance action
that calls `api.rescan()`, reports the indexed file count in the status bar, and
is disabled when no repository is open.

## Backend feature enforcement

- `watcher`: do not start the notify watcher when the group is disabled. Takes
  effect on the next repository open; Settings explains this.
- `revisions`: pass no retention on save so no new snapshots are captured.
  Existing revisions stay on disk and restore remains available if the feature
  is re-enabled.
- All other disabling is front-end visibility plus action/shortcut guards.
- Disabling must never delete settings, tags, pins, recents, custom order,
  revisions, or files.
