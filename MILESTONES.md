# Milestones and implementation notes

The build follows the milestone order in `instructions.md` section 8. All milestones are implemented in this repository. Packaging verification is split between the Windows build performed here and the Linux CI workflow in `.github/workflows/build.yml`.

## Milestone 1: window, identity, empty state, installers

- Window title and product name: Plainfold.
- Icon master: `assets/icon-master.png` (1024 by 1024), generated by `scripts/gen-icon.mjs`; a blank page with a cursor. Platform icons are produced by `tauri icon`.
- Bundle identifier: `com.plainfold.app` (placeholder until the owner supplies one).
- Publisher: Plainfold.
- Installer targets: `"all"` so Windows builds NSIS and Linux builds `.deb` and `.rpm`.
- Empty state explains the plain-file model.

## Milestone 2: open a vault and show the tree

- Native folder picker, canonical vault root, no hidden files created.
- Tree lists folders before files; name sort is case-insensitive.
- Default sort can be name, modified (newest first), or size (smallest first).
- Custom drag order is stored per folder in the index and takes precedence within each group.
- Symlinks are shown as links but never recursed into.

## Milestone 3: open, edit, save

- Encoding detection: UTF-8, UTF-8 with BOM, UTF-16 LE BOM, UTF-16 BE BOM.
- Invalid encodings open read-only with a notice; no silent conversion.
- Line endings detected on open and preserved on save. Empty new files use CRLF on Windows and LF elsewhere.
- Saves are atomic and keep the original on failure.
- Read-only above 5 MB, and read-only for invalid encodings.
- Files above 8 MB show only their beginning, still read-only, so a huge file cannot exhaust memory.
- Ctrl+S saves. Switching files, opening a vault, and closing the window confirm unsaved edits.
- Tab inserts spaces; width comes from settings.
- Wrap is off by default, with a toggle.
- Highlighting only for json, xml, html, css, js, bat (shell syntax), and log (plain text). No Markdown highlighting, rendering, or execution.

## Milestone 4: create and delete

- New items are created in the selected folder or the selected file's parent.
- A name containing `/` creates intermediate folders in one step.
- Rejected characters: `\ : * ? " < > |` and control characters. `/` is a path separator only.
- Windows also rejects CON, PRN, AUX, NUL, COM1-COM9, LPT1-LPT9, and names ending in a dot or space.
- Existing items are refused.
- Deletes confirm and use the operating system trash. Permanent deletion is not offered.

## Milestone 5: search

- FTS5 index with `unicode61` tokenization, case-insensitive.
- Search covers both names (`LIKE`) and contents (FTS5).
- Files above 2 MB are indexed by name only.
- Results show path, line number, and matching line; clicking opens at that line.
- The watcher updates the index; Rescan clears only file rows and rebuilds, preserving tags, pins, recents, and custom order.

## Milestone 6: settings

- `settings.json` in the OS config folder, written atomically.
- Missing file: defaults silently. Corrupt file: defaults plus a notice.
- Settings screen: theme, font family, font size, default sort, default vault, tab width.
- Theme follows the system unless light or dark is chosen.

## Milestone 7: organization

- Tags live only in the index and are shown in the file header and as tree filters.
- Pins are shown above the tree; recent files are the 20 most recent opens.
- Custom order is drag-and-drop within a folder only. Cross-folder moves are not implemented (see decision 3).
- Index schema includes an unused `links` table so double-bracket links can be added later without a data migration.

## Milestone 8: external changes

- `notify` watches the vault recursively, debounced at 250 ms.
- A clean open file reloads automatically.
- A dirty open file keeps its edits and shows a notice.
- Tree, tags, pins, and recents refresh after external changes.

## Milestone 9: packaging verification

- Windows release build, NSIS installer, silent install, launch, and uninstall were verified locally; see `PACKAGING.md`.
- Debian-family and Fedora-family packages are built by the CI matrix on the respective distributions. Cross-building `.deb`/`.rpm` from Windows is not supported by Tauri.
- An install/launch test on each family remains an owner or CI runner step because this workspace is Windows-only.

## Known limitations

- Packaging is verified on Windows here. Linux packages are configured and built by CI but were not installed on a Debian or Fedora machine in this workspace.
- Search is case-insensitive through SQLite `LIKE` for names, which folds ASCII case; non-ASCII name casing relies on SQLite's behavior. Contents use FTS5 Unicode case folding.
- Linux file or folder names that are not valid UTF-8 are skipped by the tree and index because the IPC and settings layer carries UTF-8 strings.
- The app has no rename/move feature in v1, by decision.
- The bundled front-end chunk exceeds Vite's default 500 kB warning because CodeMirror and its language modes are bundled with no code splitting. Nothing is fetched at runtime.
