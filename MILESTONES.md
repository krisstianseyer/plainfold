# Milestones and implementation notes

The build follows the milestone order in `instructions.md` section 8. All milestones are implemented in this repository. Packaging verification combines local Windows builds, a local Ubuntu 24.04 WSL build, and the Linux CI workflow in `.github/workflows/build.yml`.

## Milestone 1: window, identity, empty state, installers

- Window title and product name: Plainfold.
- Icon master: `assets/icon-master.png` (1024 by 1024), generated by `scripts/gen-icon.mjs`; a blank page with a cursor. Platform icons are produced by `tauri icon`.
- Bundle identifier: `com.plainfold.app` (placeholder until the owner supplies one).
- Publisher: Plainfold.
- Installer targets: `"all"` so Windows builds NSIS and Linux builds `.deb` and `.rpm`.
- Empty state explains the plain-file model.

## Milestone 2: open a vault and show the tree

- Native folder picker, canonical vault root. `.revisions` is the only app-created hidden folder and is excluded from the tree.
- Tree lists folders before files; name sort is case-insensitive.
- Default sort can be name, modified (newest first), or size (smallest first).
- Custom drag order is stored per folder in the index and takes precedence within each group.
- Symlinks are shown as links but never recursed into.

## Milestone 3: open, edit, save

- Encoding detection: UTF-8, UTF-8 with BOM, UTF-16 LE BOM, UTF-16 BE BOM.
- Invalid encodings open read-only with a notice; no silent conversion.
- Line endings detected on open and preserved on save. Empty new files use CRLF on Windows and LF elsewhere.
- Saves are atomic and keep the original on failure.
- Read-only above 5 MB, and read-only for invalid encodings.
- Files above 8 MB show only their beginning, still read-only, so a huge file cannot exhaust memory.
- Ctrl+S saves. Switching files, opening a vault, and closing the window confirm unsaved edits.
- Tab inserts spaces; width comes from settings.
- Wrap is off by default, with a toggle.
- Highlighting only for json, xml, html, css, js, bat (shell syntax), and log (plain text). No Markdown highlighting, rendering, or execution.

## Milestone 4: create and delete

- New items are created in the selected folder or the selected file's parent.
- A name containing `/` creates intermediate folders in one step.
- Rejected characters: `\ : * ? " < > |` and control characters. `/` is a path separator only.
- Windows also rejects CON, PRN, AUX, NUL, COM1-COM9, LPT1-LPT9, and names ending in a dot or space.
- Existing items are refused.
- Deletes confirm and use the operating system trash. Permanent deletion is not offered.

## Milestone 5: search

- FTS5 index with `unicode61` tokenization, case-insensitive.
- Search covers both names (`LIKE`) and contents (FTS5).
- Files above 2 MB are indexed by name only.
- Results show path, line number, and matching line; clicking opens at that line.
- The watcher updates the index; Rescan clears only file rows and rebuilds, preserving tags, pins, recents, and custom order.

## Milestone 6: settings

- `settings.json` in the OS config folder, written atomically.
- Missing file: defaults silently. Corrupt file: defaults plus a notice.
- Settings screen: theme, font family, font size, default sort, default vault, tab width.
- Theme follows the system unless light or dark is chosen.

## Milestone 7: organization

- Tags live only in the index and are shown in the file header and as tree filters.
- Pins are shown above the tree; recent files are the most recent opens. Settings default to 5 pinned and 5 recent entries, configurable from 1-100.
- Custom order is drag-and-drop within a folder only. Cross-folder moves are not implemented (see decision 3).
- Index schema includes an unused `links` table so double-bracket links can be added later without a data migration.

## Milestone 8: external changes

- `notify` watches the vault recursively, debounced at 250 ms.
- A clean open file reloads automatically.
- A dirty open file keeps its edits and shows a notice.
- Tree, tags, pins, and recents refresh after external changes.

## Milestone 9: packaging verification

- Windows release build, NSIS installer, silent install, launch, and uninstall were verified locally; see `PACKAGING.md`.
- Ubuntu 24.04 (Debian family, WSL): `.deb` built with Tauri, installed with `apt`, passed an `ldd` missing-library check, and removed cleanly.
- `.rpm` built from the same source with `rpmbuild` on Ubuntu; RPM metadata and dependencies were inspected. The Fedora CI job installs the RPM; desktop launch remains a VM step.

## Desktop shortcuts and macOS scope

- macOS is deferred as a nice-to-have. The stack is portable, but there is no macOS build, signing, or notarization in this release.
- Windows MSI always creates Start Menu and Desktop shortcuts. NSIS always creates the Start Menu shortcut and offers a default-checked Desktop shortcut on its finish page.
- Linux packages install the application-menu entry. On first launch, the app offers once to create a per-user `.desktop` shortcut on the Desktop; the choice is recorded in `settings.json`.
- The Linux shortcut writes only to the user's XDG Desktop folder. No package post-install script or root access is used.

## Autosave and revisions

- Autosave modes: off (default), after idle (default 20s), and fixed interval (default 120s, minimum 120s). Autosave runs only while the current file is dirty.
- Revisions live in `vault/.revisions/<relative file path>/<UTC timestamp>.gz`.
- Snapshots are gzip-compressed full copies of the previous on-disk bytes, captured before a save replaces them.
- Retention uses Grandfather-Father-Son rotation. Defaults: 24 hourly, 7 daily, 4 weekly, 12 monthly, 100 yearly. Each tier is a setting from 0-1000; 0 disables that tier.
- Buckets use local time; weeks are ISO weeks. Each tier keeps the newest snapshot in each of its N most recent active buckets, and tiers are unioned, so one snapshot can satisfy several tiers.
- Rotation runs after each capture. Disabling every tier stops new revisions.
- File context menu: “Show revisions…”. Restoring captures the current file as a revision first, then writes the chosen snapshot.
- `.revisions` is excluded from the tree, search index, watcher, moves, and deletes. The app refuses to create or target that name.
- Revision paths are canonicalized and rejected if they resolve outside the vault. Restore is capped at 5 MB decompressed.

## Known limitations

- Windows and Debian-family installs are verified locally. Fedora-family installation runs in CI, but a Fedora desktop launch remains a VM step.
- The local `.deb` and `.rpm` artifacts predate the Linux desktop-shortcut change. Rebuild them and verify the first-run prompt in a real desktop session before release.
- Search is case-insensitive through SQLite `LIKE` for names, which folds ASCII case; non-ASCII name casing relies on SQLite's behavior. Contents use FTS5 Unicode case folding.
- Linux file or folder names that are not valid UTF-8 are skipped by the tree and index because the IPC and settings layer carries UTF-8 strings.
- The app has no rename/move feature in v1, by decision.
- The bundled front-end chunk exceeds Vite's default 500 kB warning because CodeMirror and its language modes are bundled with no code splitting. Nothing is fetched at runtime.

## Validation performed

- Rust: 55 unit tests and 9 integration tests pass on Windows; 57 unit tests and 9 integration tests pass on Ubuntu 24.04 WSL, including Linux XDG desktop-shortcut parsing and file creation. Coverage includes symlink escape, corrupt-index recovery, atomic rename failure cleanup, encoding mismatches, oversized saves, Unicode name search, drag-reorder persistence, move/index migration, GFS revision capture/restore/rotation, and the exact 2 MiB content-index boundary.
- Clippy is clean with `-D warnings` on Windows and Linux.
- Front end: 11 tree-helper and link tests pass; production bundle builds with no unsafe DOM APIs and no external URLs.
- Windows NSIS installer was rebuilt after the desktop-shortcut changes. The NSIS finish-page Desktop shortcut option is checked by default.
- Real app on Windows: opened a default vault, opened a file in the tree, edited it, saved with Ctrl+S, and confirmed CRLF line endings survived on disk.
- Real app search: found newly saved text, displayed the correct line number, and exposed the result through the accessibility tree.
- Real app settings: changed the font family through the settings dialog and confirmed `settings.json` persisted it.
- Real app watcher: an external edit reloaded a clean open file; an external edit with unsaved changes kept the edits and showed the notice.
- Real app close behavior: closing with unsaved changes showed the confirmation dialog; cancelling left the app running.
- Real app unsaved switching: selecting another file while dirty showed the confirmation dialog; cancelling kept the dirty file open.
- Real app size limit: a 6 MB file opened read-only, showed the 5 MB notice, and disabled Save.
- Real app organization: pinned and unpinned through the context menu, added tags through the tag dialog, and saw both in the UI.
- Real app tag filter: clicking a tag chip reduced the tree to the tagged file and hid unrelated files and folders.
- Persistence: pins and tags survived an app restart; the tagged file's bytes did not contain the tag, and the vault stayed free of app-created metadata files.
- Real app create/delete: created a nested path in one step, rejected an invalid colon name with the plain-language error, and deleted a file to the trash with confirmation.
- Real app Rescan: reported the correct indexed file count after deleting a file.
- Real app editor: Tab inserted four spaces, Save preserved CRLF, the wrap toggle switched to Wrap on, and a `.md` file displayed `# Heading` and literal asterisks as source.
- Packaging: both NSIS and MSI installers completed install, launch, and uninstall; EXE metadata reports Plainfold and the ICO contains a 16 by 16 frame.
- Linux packaging: `.deb` install/remove and library resolution verified on Ubuntu 24.04; `.rpm` artifact built, digest-checked, and inspected.
- Static checks: `cargo clippy --all-targets` is clean and `npm audit --omit=dev` reports zero vulnerabilities.
